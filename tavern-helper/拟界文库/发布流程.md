# 拟界文库版本发布流程

## 版本结构

- `release.json` 是脚本发布版本的唯一来源，`index.ts` 从这里注入界面的 `APP_VERSION`，打包工具也从这里读取版本。
- 当前发布版本为 `1.7.6`，承接本地构建 `1.7.3` 与旧界面版本 `1.7.2D`。后续固定采用 `1.7.X`，日常修复与发布只递增非负整数
  `X`；升级系列需明确决定，并同步修改打包工具的校验规则。
- 界面显示 `1.7.X`，产物名为 `loreframe-1.7.X.js`，Git 标签为 `loreframe-v1.7.X`，与预设助手的 `v0.42.X` 分开。
- 补丁名称里的 `TauriTavern 2.2.0` 是兼容目标版本，不是文库版本。
- 存储 key 的 `v1` /
  `v2`、IndexedDB 版本、提示词导出格式版本是数据协议版本，不能跟随日常发布递增。需要迁移时单独设计兼容逻辑。
- 更新日志与发布号独立维护；不要仅因打包而改写历史日志或提示词。

## 本地构建

1. 修改源码，并在 `release.json` 中确定本次版本。本次使用 `1.7.6`。
2. 在模板项目根目录执行：

   ```powershell
   pnpm release:loreframe
   ```

   此命令依次执行 `pnpm test:loreframe` 回归、文库目录 ESLint、项目生产构建和发布打包；任何步骤失败都会停止。

3. 检查输出目录：

   ```text
   release/loreframe-v1.7.X/
   ├─ loreframe-1.7.X.js
   └─ manifest.json
   ```

   JS 来自
   `dist/util/酒馆助手脚本/线上功能脚本/index.js`。清单包含名称、版本、标签、文件名和 SHA-256。目录已存在时拒绝覆盖；正式交付后必须递增版本，尚未交付的失败构建可人工检查并移走对应目录后重试。

4. 将完整 JS 内容导入酒馆助手脚本进行验证。该产物是拟界文库完整脚本，不是单独补丁；升级后停用旧的独立尺寸补丁，避免重复样式。

## 发布仓库结构

发布仓库为 https://github.com/colerith/LoreFrame ，主分支为 `main`。按以下结构同步：

```text
file/
  loreframe-1.7.X.js
  loreframe-1.7.X.manifest.json
tavern-helper/
  拟界文库/                  # 本目录的完整源码与文档，不复制 .git / .agents
scripts/
  package-loreframe.mjs      # 模板项目中的发布打包工具副本
```

源码采用当前 raw 片段拼装机制，在模板项目中恢复到 `src/util/酒馆助手脚本/线上功能脚本`
后构建；发布仓库源码目录本身不是独立 npm 项目。保留模板项目的依赖锁文件及 webpack 配置作为构建环境依据。

## 上传步骤

1. 完成本地构建与下方人工验证，复制版本产物、清单和源码至已确认的发布仓库。
2. 更新发布仓库 README 和版本说明中的版本号、下载地址；检查清单的 SHA-256 与上传 JS 一致。
3. 只暂存此次文库文件，不使用 `git add .`，不修改或暂存预设助手、广告配置等无关文件。检查 `git diff --cached`。
4. 在发布仓库中提交并建立独立标签（下例为本次版本；分支名按仓库实际情况选择）：

   ```powershell
   git commit -m "release: loreframe v1.7.6"
   git tag -a "loreframe-v1.7.6" -m "LoreFrame v1.7.6"
   git push origin HEAD
   git push origin "loreframe-v1.7.6"
   ```

5. CDN 地址使用固定标签：`https://cdn.jsdelivr.net/gh/colerith/LoreFrame@loreframe-v1.7.X/file/loreframe-1.7.X.js`。版本占位符必须替换成实际发布号；验证响应内容与本地产物一致后才交付链接。
6. 回滚使用前一版本的固定标签链接，不移动旧标签、不覆盖旧版本文件。涉及数据协议迁移时，应先确认旧代码仍能读取新数据。

## 发布前验证

- TauriTavern 2.2.0：面板被标记 `data-tt-mobile-surface="fullscreen-window"`
  时，宽高扣除宿主安全区；检查横竖屏、顶部安全区和底部/键盘占用区域。
- 普通酒馆：非全屏面板的拖拽、缩放、全屏切换、悬浮球不受新增选择器影响。
- 重载、卸载：宿主样式随原有 launcher 样式一起移除，重新挂载不重复注入。
- 页面版本与 `release.json`、产物文件名、清单和标签一致。
- 冒烟检查已有页面读取、候选切换、手动生成及设置保存；确认旧缓存与数据 key 未被改动。
- ESLint 和构建通过不等于完成 TauriTavern 真机验证，发布说明应准确记录实际验证范围。
